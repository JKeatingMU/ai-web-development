Overview

What is n8n?

n8n (pronounced "n-eight-n") is an open-source workflow automation tool. You build workflows visually by connecting nodes — each node does one thing. Nodes pass data between themselves as items.

What makes n8n relevant here
  • Built-in AI Agent node — runs the ReAct loop you learned in E1 without writing the loop code yourself
  • HTTP Request node — calls any REST API, including your Reading List API
  • 400+ integrations — Slack, Gmail, Postgres, Google Sheets, and more, as pre-built nodes
  • Self-hostable — run locally for development, deploy for production
n8n vs writing agent code (E1)
  • The loop, tool routing, and message history are handled by n8n — you configure, not code
  • Human-in-the-loop approval is a node, not a pattern to implement
  • Connections between steps are visual — easier to audit and explain
  • But: less flexible than code for complex logic; n8n expressions have limits

Fundamental Concept

The Item Model

n8n passes data as an array of items between nodes. Each item is a JSON object with a json field. When a node receives multiple items, it processes each one independently.

What one item looks like
[ { json: { id: 1, title: "DDIA", author: "Kleppmann", status: "unread" } }, { json: { id: 2, title: "SICP", author: "Abelson", status: "reading" } } ]
Why this matters
  • →HTTP Request returns the API response wrapped in an item. To access a field: {{ $json.title }}
  • →If your API returns an array, n8n wraps the whole array in one item. Use Split Out to turn it into multiple items — one per book.
  • →A node that receives 5 items runs its logic 5 times — once per item. This is how "process each book" works.
Dynamic Values

Expressions: Referencing Data Between Nodes

Static values are typed directly into a field. Dynamic values — data from previous nodes — are written as expressions using double curly braces: {{ }}.

ExpressionReturnsUse case
{{ $json.title }} The title field from the current item Include a book title in a message body
{{ $json.id }} The id field from the current item Build a URL: https://api/books/{{ $json.id }}
{{ $node["HTTP Request"].json.status }} The status field from a specific named node Reference a node that isn't the immediate parent
{{ $items().length }} Number of items in the current batch Include item count in a summary message
{{ new Date().toISOString() }} Current timestamp Timestamp in a log or email subject
The expression editor (click the expression icon next to any field) has autocomplete for $json, $node, and built-in n8n variables. Use it — do not guess syntax from memory.

Authentication

Credentials: Storing Auth Securely

n8n stores API keys, passwords, and tokens in credentials — encrypted, named objects you create once and reference in nodes. Never paste secrets directly into node fields.

For your Reading List API (JWT)
  1. Go to Settings → Credentials → New
  2. Choose Header Auth
  3. Name: Reading List API
  4. Header name: Authorization
  5. Header value: Bearer <your-jwt>
For Anthropic (Claude)
  1. Create a Anthropic credential (type is built in)
  2. Paste your sk-ant-... API key
  3. Reference it in: AI Agent node → Model → Claude → Credential
  4. n8n encrypts and stores it — never visible in workflow JSON exports
Never export workflow JSON and commit it to git if it contains inline credentials. Always use the Credentials system — the workflow JSON will then contain only a credential reference ID, not the secret itself.
The Core Node

The HTTP Request Node

The HTTP Request node calls any REST API. You configure it like a curl command — method, URL, headers, body. Use expressions to make values dynamic.

AI Agent Node

The AI Agent Node: What It Does

The AI Agent node runs the Reason → Act → Observe loop internally. You configure: the model, the tools it can use, the memory, and the system prompt. n8n handles the loop.

Configuration
SettingWhat to put here
ModelClaude (Anthropic credential) or OpenAI
System PromptThe agent's role + constraints
Prompt (user)The goal — usually from a previous node via expression
ToolsSub-nodes connected below the agent node
MemoryBuffer Memory node (in-context) or external DB
Tools are child nodes
AI Agent ├── HTTP Request Tool │ (GET /api/books) ├── HTTP Request Tool │ (PATCH /api/books/:id) └── Code Tool (custom logic)

Each child node is a tool the agent can call. The agent decides which one to invoke based on the task.

The Reading Checklist

How to Read an n8n Workflow

When you open an unfamiliar workflow — or review one an AI has generated — work through these questions.

  • 1 Where does it start? Find the trigger node (green border, leftmost). Is it a webhook, schedule, or manual trigger? What starts the workflow?
  • 2 What data flows? Trace the item structure from the first HTTP Request node. Is the API response an array that needs Split Out? What fields does downstream logic reference?
  • 3 Where are the credentials? Check each action node — is authentication configured via a credential, or is a key pasted inline? Inline keys are a problem.
  • 4 What does the AI Agent do? Find the system prompt. List the tool nodes connected below it. Identify what the agent can read vs what it can modify.
  • 5 Is there a human gate? For any irreversible action (send email, PATCH/DELETE a record), is there a "Wait for Approval" node before it executes?
Prompt Reflection

What You Built With vs What You Learned

If you used an AI assistant to generate an n8n workflow (or asked it to explain one), answer these before moving to E3.

🤔 Questions to answer without re-reading the AI's explanation
  • Name every node in the workflow. For each: what type is it, and what does it do?
  • Find one expression in the workflow. Explain what data it reads and from where.
  • Does the workflow handle multiple items at once? If so, where does it split or merge them?
  • Where are credentials stored? Confirm no secrets appear in the workflow's node configuration fields.
  • Is there any irreversible action? If so, is there a human gate before it?
The goal is fluency, not memorisation. You should be able to look at any n8n workflow and narrate what it does — node by node — in plain English. That is the skill E3 and E4 build on.
