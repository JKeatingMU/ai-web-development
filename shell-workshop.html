Terminal, Shell, Command Line

  • TerminalThe window you type in. A graphical interface to the shell. (iTerm2, Terminal.app, Windows Terminal)
  • ShellThe program that reads your commands and runs them. zsh (macOS default), bash (Linux default), PowerShell (Windows)
  • CommandA program you run by name. node, npm, psql, curl, git — all programs found somewhere on your system.
  • PromptThe line where you type. Usually shows your current directory. The $ symbol means "ready for input."
shell prompt and basic commands
username@machine ~/projects/my-api $ $ node --version v22.0.0 $ npm --version 10.5.0 $ whoami username
macOS / Linux: use Terminal.app, iTerm2, or any terminal emulator. The shell is zsh or bash. Windows: use Windows Terminal with WSL2 (Ubuntu) or Git Bash. The commands in this course assume a Unix-like shell.

Creating, Moving, Deleting

file operations
$ mkdir my-project # create a directory $ mkdir -p a/b/c # create nested directories $ touch server.js # create an empty file $ mv server.js app.js # rename a file $ mv app.js src/ # move a file into src/ $ cp .env.example .env # copy a file $ cp -r src/ backup/ # copy a directory $ rm notes.txt # delete a file $ rm -rf node_modules/ # delete a directory recursively
  • mkdirMake directory. -p creates all parent dirs.
  • touchCreate empty file (or update timestamp).
  • mvMove or rename. Works for both files and directories.
  • cpCopy. Use -r for directories.
  • rmDelete — permanent. No trash bin. No undo.
rm -rf is irreversible. It deletes everything in the path recursively with no confirmation. Before running any rm -rf command — especially AI-generated ones — verify the path is exactly what you intend. A stray space can destroy your project.

Reading File Contents

reading file contents
$ cat server.js # print entire file $ head -n 20 server.js # first 20 lines $ tail -n 20 server.js # last 20 lines $ tail -f server.log # follow a file live ^C to stop $ less server.js # page through file # space = next page, b = back, q = quit, /term = search $ wc -l server.js # count lines 87 server.js
  • catPrint entire file. Good for small files; overwhelming for large ones.
  • head / tailFirst or last N lines. tail -f follows a log file as it grows — invaluable for watching a server's output.
  • lessPage through large files. Searchable. Press q to quit.
  • wc -lWord count — with -l counts lines. Useful for checking file size.
Reading server logs: When your Express server is running with node --watch server.js, its console.log output goes to the terminal. If something breaks, look there first — the error message and stack trace tell you exactly what went wrong.

The PATH — How the Shell Finds Commands

PATH — finding executables
$ echo $PATH /usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin $ which node /usr/local/bin/node $ which psql /usr/local/bin/psql # If you see "command not found": $ node zsh: command not found: node # → node is not in any PATH directory # nvm adds itself to PATH in ~/.zshrc: export PATH="$HOME/.nvm/versions/node/v22.0.0/bin:$PATH"
  • $PATHA colon-separated list of directories. When you type node, the shell searches each directory in order for a file named node.
  • whichShows where a command's executable lives. which node tells you exactly which installation is being used.
  • nvmManages multiple Node.js versions by adding the active version's bin/ directory to PATH. That's why nvm use 22 changes which node you run.
  • brew / aptPackage managers install programs into standard PATH directories, which is why after brew install jq you can just type jq.

Environment Variables

environment variables
# Set a variable in the current session $ export DATABASE_URL="postgresql://localhost/mydb" $ export PORT=3001 $ export NODE_ENV=development # Read it back $ echo $DATABASE_URL postgresql://localhost/mydb # All current env vars $ env # ... long list # In Node.js: # process.env.DATABASE_URL # process.env.PORT # process.env.NODE_ENV
  • exportMakes the variable available to any program started in this session. Without export, it's only in the shell itself.
  • $VARRead a variable. $DATABASE_URL expands to its value. Unset variables expand to an empty string.
  • process.envIn Node.js, all environment variables are available as properties of process.env. Express reads process.env.PORT, process.env.DATABASE_URL, etc.
  • Session scopeVariables set with export last for the current terminal session only. A new terminal window starts fresh.
Convention: environment variable names are UPPER_CASE. This distinguishes them from shell variables and code variables.

The .env File — Secrets and Config

.env and .env.example
# .env — your actual secrets (NEVER commit this) DATABASE_URL=postgresql://localhost:5432/reading_list PORT=3001 JWT_SECRET=a-long-random-string-here NODE_ENV=development # .env.example — template (commit this) DATABASE_URL=postgresql://localhost:5432/your_db_name PORT=3001 JWT_SECRET=replace-with-a-long-random-string NODE_ENV=development
  • .envContains real secrets. In .gitignore. Never committed. Different on every machine.
  • .env.exampleTemplate with placeholder values. Committed to git. Tells collaborators (and future you) what variables are needed.
  • dotenvimport 'dotenv/config' at the top of your server file loads .env into process.env automatically.
Never commit .env to git. If a secret reaches a public repository, assume it is compromised — rotate it immediately. Railway and Vercel have a dashboard for setting production env vars; they never go in the code.
How to create a strong JWT_SECRET: openssl rand -base64 32 in the terminal. 32 bytes of random data, base64 encoded.

Pipes — Connecting Commands

pipes and redirection
# Pipe: output of left becomes input of right $ curl -s http://localhost:3001/api/books | jq . # Chain multiple pipes $ cat server.js | grep "app\." | wc -l 12 # grep: filter lines matching a pattern $ ls -la | grep ".js" # sort and count unique values $ cat access.log | sort | uniq -c | sort -rn # Redirect to a file $ curl -s .../books > books.json $ curl -s .../books >> books.json # append # Redirect stderr to stdout $ node server.js 2>&1 | tee server.log
  • |The pipe operator. Takes stdout of the left command and feeds it as stdin to the right command. Chains can be as long as you need.
  • >Redirect output to a file. Creates or overwrites.
  • >>Append to a file. Creates if it doesn't exist.
  • 2>&1Redirect stderr (error output, stream 2) to stdout (stream 1). Useful when errors would otherwise be invisible.
  • grepFilter lines matching a regex pattern. -i for case-insensitive, -v to invert.
The curl ... | jq . pattern you've used throughout this course is a pipe. curl writes JSON to stdout. The | passes it to jq, which pretty-prints it to your terminal.

Chaining Commands — &&, ||, ;

chaining operators
# && — run next only if previous succeeded (exit code 0) $ npm install && node server.js $ psql $DATABASE_URL < schema.sql && echo "Migration done" # || — run next only if previous FAILED $ ping -c1 localhost || echo "No network" # ; — run next regardless $ npm run build; npm start # Practical: create project and enter it $ mkdir my-api && cd my-api && npm init -y # Practical: migrate and start $ psql $DATABASE_URL < schema.sql && \ npm install && \ node server.js
  • &&"And then — if success." The most common. Stops the chain on first failure. Used in npm scripts, deployment steps, CI pipelines.
  • ||"Or — if failure." Good for fallback behaviour or error messages.
  • ;"Then — always." Runs both commands regardless of success or failure. Rarely what you want in automated scripts.
  • Exit codesPrograms signal success (0) or failure (non-zero) with an exit code. $? holds the exit code of the last command.
AI often generates multi-step setup commands joined by &&. Now you know why: if npm install fails, you don't want node server.js to run with incomplete dependencies.

Command Substitution — Capturing Output

command substitution with $()
# $() captures the output of a command as a string # Capture a JWT token $ TOKEN=$(curl -s -X POST http://localhost:3001/auth/login \ -H 'Content-Type: application/json' \ -d '{"email":"alice@example.com","password":"abc"}' \ | jq -r '.token') # Confirm it worked $ echo $TOKEN eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... # Capture date for a filename $ DATE=$(date +%Y-%m-%d) $ cp backup.sql backup-$DATE.sql # Capture line count $ LINES=$(wc -l < server.js) $ echo "server.js has $LINES lines"
  • $()Runs the command inside and substitutes its stdout in place. The outer shell sees the captured text, not the original command.
  • TOKEN=$(...)The entire TOKEN capture pattern from the curl deck — this is how it works. The jq -r '.token' extracts just the token string from the JSON response.
  • Variable in strings$VARNAME expands inside double-quoted strings. In single-quoted strings, it does NOT expand. That's why you need double quotes when using variables.
  • BackticksThe older syntax `command` is equivalent to $(command). Prefer $() — it nests more clearly.

Controlling Running Programs

process management
# Stop a running program Ctrl+C # Suspend (pause) a running program Ctrl+Z # Resume in background $ bg # Resume in foreground $ fg # Run in background from the start $ node server.js & [1] 12345 # PID printed # List background jobs $ jobs [1]+ Running node server.js # Kill by PID $ kill 12345 $ kill -9 12345 # force kill (SIGKILL) # Find what's using port 3001 $ lsof -i :3001
  • Ctrl+CSends SIGINT — asks the program to stop cleanly. Use this to stop your dev server.
  • Ctrl+ZSuspends the process. You get your prompt back. The process is paused, not killed.
  • &Run a command in the background. Your prompt returns immediately. The process keeps running.
  • lsof -i :PORTShows what process is listening on a port. If "address already in use" — use this to find what's occupying port 3001.
Keyboard shortcuts in the shell: Ctrl+A — beginning of line. Ctrl+E — end of line. Ctrl+R — search command history. Ctrl+L — clear screen. ↑/↓ — navigate history. !! — repeat last command.

~/.zshrc — Your Shell's Startup File

~/.zshrc example
# ~/.zshrc — loaded every time you open a terminal # Make ls use colour alias ls='ls --color=auto' alias ll='ls -la' alias la='ls -A' # Shortcut to project directory alias api='cd ~/projects/my-api' # Always set NODE_ENV for development export NODE_ENV=development # nvm (added automatically by nvm install) export NVM_DIR="$HOME/.nvm" [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh" # Reload after editing: # source ~/.zshrc
  • ~/.zshrcThe file zsh reads when it starts. ~ means your home directory. On macOS with bash it's ~/.bashrc or ~/.bash_profile.
  • aliasCreate a shortcut. alias ll='ls -la' means typing ll runs ls -la. Saved permanently once in .zshrc.
  • exportVariables set here are available to every program you run in every terminal session. Good place for EDITOR, NODE_ENV etc.
  • sourcesource ~/.zshrc reloads the file without closing the terminal. Run this after editing .zshrc.
Don't blindly copy .zshrc snippets from the internet. Understand each line before adding it. AI can generate .zshrc snippets — ask it to explain each line.

Writing a Shell Script

test-api.sh
#!/usr/bin/env bash # test-api.sh — basic API smoke test BASE="http://localhost:3001" # 1. Health check echo "--- Health check ---" curl -s $BASE/api/health | jq -r '.status' # 2. Login and capture token echo "--- Login ---" TOKEN=$(curl -s -X POST $BASE/auth/login \ -H 'Content-Type: application/json' \ -d '{"email":"alice@example.com","password":"test123"}' \ | jq -r '.token') if [ -z "$TOKEN" ] || [ "$TOKEN" = "null" ]; then echo "Login failed — is the server running?" exit 1 fi echo "Token captured" # 3. Create a book echo "--- Create book ---" curl -s -X POST $BASE/api/books \ -H "Authorization: Bearer $TOKEN" \ -H 'Content-Type: application/json' \ -d '{"title":"Test Book","author":"Tester"}' | jq '{id,title}'
  • #!/usr/bin/env bashThe shebang line — tells the OS which interpreter to use. Always the first line of a script.
  • VariablesBASE="..." — assign without spaces around =. Read with $BASE.
  • if [ -z ... ]Test if a string is empty (-z). -n tests non-empty. [ "$VAR" = "value" ] tests equality.
  • exit 1Stop the script and signal failure (non-zero exit code). exit 0 signals success.
  • Make executablechmod +x test-api.sh, then run with ./test-api.sh

Reading AI-Generated Shell Commands

AI generates shell commands constantly — curl examples, npm scripts, deployment instructions, database setup commands. Always read a shell command before running it. Unlike a code file you can review and test in stages, a shell command executes immediately and some effects are irreversible. AI is often overconfident about shell syntax: it may use the wrong flags for your OS, assume a tool is installed, or generate rm -rf patterns you should scrutinise carefully.
AI-generated commands you'll see in this course: npm install && node server.js · psql $DATABASE_URL < schema.sql · TOKEN=$(curl ... | jq -r '.token') · export $(grep -v '^#' .env | xargs). Now you can read every token of these commands and understand exactly what they do.
Using AI to learn shell: Ask AI to explain any command you don't recognise. curl -s -X POST ... -H ... -d ... — ask "what does each flag do?". Ask it to write a test script and explain each line. The AI is an excellent shell tutor when you engage with it rather than just copying.
Cross-platform note: bash scripts run on macOS and Linux. Windows users should use WSL2 or Git Bash. PowerShell has different syntax. If AI generates a shell command, ask it to confirm which shell it assumes.
