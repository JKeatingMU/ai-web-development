Terminal & Shell

Key concept

Every curl command in this course, every npm install, every psql connection, every node server.js — all of these run in the terminal. This deck gives you the vocabulary to understand, modify, and write your own shell commands.

Terminal, Shell, Command Line

  • Terminal — The window you type in. A graphical interface to the shell. (iTerm2, Terminal.app, Windows Terminal)
  • Shell — The program that reads your commands and runs them. zsh (macOS default), bash (Linux default), PowerShell (Windows)
  • Command — A program you run by name. node, npm, psql, curl, git — all programs found somewhere on your system.
  • Prompt — The line where you type. Usually shows your current directory. The $ symbol means "ready for input."

macOS / Linux : use Terminal.app, iTerm2, or any terminal emulator. The shell is zsh or bash. Windows : use Windows Terminal with WSL2 (Ubuntu) or Git Bash. The commands in this course assume a Unix-like shell.

Where Am I? Moving Around

  • pwd — P rint W orking D irectory — where you are right now
  • ls — L i s t files in current directory. -l for details, -a to show hidden files (starting with .)
  • cd — C hange D irectory. cd path to go there, cd .. to go up, cd ~ for home
  • Tab — Press Tab to autocomplete paths and filenames — use it constantly
  • ↑ / ↓ — Navigate command history without retyping

Creating, Moving, Deleting

  • mkdir — Make directory. -p creates all parent dirs.
  • touch — Create empty file (or update timestamp).
  • mv — Move or rename. Works for both files and directories.
  • cp — Copy. Use -r for directories.
  • rm — Delete — permanent. No trash bin. No undo.
Gotcha

rm -rf is irreversible. It deletes everything in the path recursively with no confirmation. Before running any rm -rf command — especially AI-generated ones — verify the path is exactly what you intend. A stray space can destroy your project.

Reading File Contents

  • cat — Print entire file. Good for small files; overwhelming for large ones.
  • head / tail — First or last N lines. tail -f follows a log file as it grows — invaluable for watching a server's output.
  • less — Page through large files. Searchable. Press q to quit.
  • wc -l — Word count — with -l counts lines. Useful for checking file size.
Tip

Reading server logs: When your Express server is running with node --watch server.js, its console.log output goes to the terminal. If something breaks, look there first — the error message and stack trace tell you exactly what went wrong.

The PATH — How the Shell Finds Commands

  • $PATH — A colon-separated list of directories. When you type node, the shell searches each directory in order for a file named node.
  • which — Shows where a command's executable lives. which node tells you exactly which installation is being used.
  • nvm — Manages multiple Node.js versions by adding the active version's bin/ directory to PATH. That's why nvm use 22 changes which node you run.
  • brew / apt — Package managers install programs into standard PATH directories, which is why after brew install jq you can just type jq.

Environment Variables

  • export — Makes the variable available to any program started in this session. Without export, it's only in the shell itself.
  • $VAR — Read a variable. $DATABASE_URL expands to its value. Unset variables expand to an empty string.
  • process.env — In Node.js, all environment variables are available as properties of process.env. Express reads process.env.PORT, process.env.DATABASE_URL, etc.
  • Session scope — Variables set with export last for the current terminal session only. A new terminal window starts fresh.
Key concept

Convention: environment variable names are UPPER_CASE. This distinguishes them from shell variables and code variables.

The .env File — Secrets and Config

  • .env — Contains real secrets. In .gitignore. Never committed. Different on every machine.
  • .env.example — Template with placeholder values. Committed to git. Tells collaborators (and future you) what variables are needed.
  • dotenv — import 'dotenv/config' at the top of your server file loads .env into process.env automatically.
Gotcha

Never commit .env to git. If a secret reaches a public repository, assume it is compromised — rotate it immediately. Railway and Vercel have a dashboard for setting production env vars; they never go in the code.

Tip

How to create a strong JWT_SECRET: openssl rand -base64 32 in the terminal. 32 bytes of random data, base64 encoded.

Pipes — Connecting Commands

  • | — The pipe operator. Takes stdout of the left command and feeds it as stdin to the right command. Chains can be as long as you need.
  • > — Redirect output to a file. Creates or overwrites.
  • >> — Append to a file. Creates if it doesn't exist.
  • 2>&1 — Redirect stderr (error output, stream 2) to stdout (stream 1). Useful when errors would otherwise be invisible.
  • grep — Filter lines matching a regex pattern. -i for case-insensitive, -v to invert.
Tip

The curl ... | jq. pattern you've used throughout this course is a pipe. curl writes JSON to stdout. The | passes it to jq, which pretty-prints it to your terminal.

Chaining Commands — &&, ||, ;

  • && — "And then — if success." The most common. Stops the chain on first failure. Used in npm scripts, deployment steps, CI pipelines.
  • || — "Or — if failure." Good for fallback behaviour or error messages.
  • ; — "Then — always." Runs both commands regardless of success or failure. Rarely what you want in automated scripts.
  • Exit codes — Programs signal success (0) or failure (non-zero) with an exit code. $? holds the exit code of the last command.
Tip

AI often generates multi-step setup commands joined by &&. Now you know why: if npm install fails, you don't want node server.js to run with incomplete dependencies.

Command Substitution — Capturing Output

  • $() — Runs the command inside and substitutes its stdout in place. The outer shell sees the captured text, not the original command.
  • TOKEN=$(...) — The entire TOKEN capture pattern from the curl deck — this is how it works. The jq -r '.token' extracts just the token string from the JSON response.
  • Variable in strings — $VARNAME expands inside double-quoted strings. In single-quoted strings, it does NOT expand. That's why you need double quotes when using variables.
  • Backticks — The older syntax `command` is equivalent to $(command). Prefer $() — it nests more clearly.

Controlling Running Programs

  • Ctrl+C — Sends SIGINT — asks the program to stop cleanly. Use this to stop your dev server.
  • Ctrl+Z — Suspends the process. You get your prompt back. The process is paused, not killed.
  • & — Run a command in the background. Your prompt returns immediately. The process keeps running.
  • lsof -i :PORT — Shows what process is listening on a port. If "address already in use" — use this to find what's occupying port 3001.

Keyboard shortcuts in the shell: Ctrl+A — beginning of line. Ctrl+E — end of line. Ctrl+R — search command history. Ctrl+L — clear screen. ↑ /↓ — navigate history. !! — repeat last command.

~/.zshrc — Your Shell's Startup File

  • ~/.zshrc — The file zsh reads when it starts. ~ means your home directory. On macOS with bash it's ~/.bashrc or ~/.bash_profile.
  • alias — Create a shortcut. alias ll='ls -la' means typing ll runs ls -la. Saved permanently once in .zshrc.
  • export — Variables set here are available to every program you run in every terminal session. Good place for EDITOR, NODE_ENV etc.
  • source — source ~/.zshrc reloads the file without closing the terminal. Run this after editing .zshrc.
Gotcha

Don't blindly copy .zshrc snippets from the internet. Understand each line before adding it. AI can generate .zshrc snippets — ask it to explain each line.

Writing a Shell Script

  • #!/usr/bin/env bash — The shebang line — tells the OS which interpreter to use. Always the first line of a script.
  • Variables — BASE="..." — assign without spaces around =. Read with $BASE.
  • if [ -z ... ] — Test if a string is empty (-z). -n tests non-empty. [ "$VAR" = "value" ] tests equality.
  • exit 1 — Stop the script and signal failure (non-zero exit code). exit 0 signals success.
  • Make executable — chmod +x test-api.sh, then run with ./test-api.sh

Reading AI-Generated Shell Commands

Gotcha

AI generates shell commands constantly — curl examples, npm scripts, deployment instructions, database setup commands. Always read a shell command before running it. Unlike a code file you can review and test in stages, a shell command executes immediately and some effects are irreversible. AI is often overconfident about shell syntax: it may use the wrong flags for your OS, assume a tool is installed, or generate rm -rf patterns you should scrutinise carefully.

AI-generated commands you'll see in this course: npm install && node server.js · psql $DATABASE_URL < schema.sql · TOKEN=$(curl ... | jq -r '.token') · export $(grep -v '^#' .env | xargs). Now you can read every token of these commands and understand exactly what they do.

Using AI to learn shell: Ask AI to explain any command you don't recognise. curl -s -X POST ... -H ... -d ... — ask "what does each flag do?". Ask it to write a test script and explain each line. The AI is an excellent shell tutor when you engage with it rather than just copying.

Cross-platform note: bash scripts run on macOS and Linux. Windows users should use WSL2 or Git Bash. PowerShell has different syntax. If AI generates a shell command, ask it to confirm which shell it assumes.

Practical work

Write a shell script (practical)
Write a script that: (1) prints today's date, (2) counts how many .js files are in the current directory tree, (3) shows the last 10 commands from your shell history.
  • The script runs without errors from a fresh terminal session
  • Each of the three tasks is handled by a distinct command or pipeline
  • You can explain what each line does and why you wrote it that way
curl + jq pipeline (practical)
Run: curl -s https://jsonplaceholder.typicode.com/todos/1 | jq '.title' Then modify the jq expression to extract a different field. If you don't have jq, install it: brew install jq or apt install jq.
  • You ran the command and received output (not a connection or parse error)
  • You successfully extracted a different field with a modified jq expression
  • You can explain what the pipe | does and why the output changes with different jq filters
